# UI Guide

## 产品气质

Turalk 是年轻化的二游社区，保持适中信息密度和明确层级，优先讨论效率、可读性与移动端体验。色彩和插画可以有社区感，但不使用过度花哨、影响性能或难以维护的视觉效果。

## 页面结构

- **首页信息流**：导航、分区入口、推荐/最新内容、明确空状态。
- **游戏分区页**：分区说明、筛选排序、帖子列表、分页。
- **帖子详情页**：标题和状态、匿名公开作者、正文、操作区、评论入口。
- **发帖页**：分区选择、标题、正文、草稿/提交状态和规则提示。
- **登录注册页**：单一主任务、清晰校验、错误恢复和隐私提示。
- **实名认证页**：说明数据用途和边界，认证步骤与状态明确，不展示敏感原文。
- **个人主页**：只展示公开资料和公开内容，不出现实名字段。
- **管理后台列表页**：表格、组合筛选、状态标签、分页、批量操作边界与审计入口。

## 组件规范

- **Button**：primary/secondary/danger，支持 loading 和 disabled；危险动作不作为默认按钮。
- **Card**：承载单一信息组，避免层层嵌套。
- **Badge**：用于短状态，不单靠颜色表达含义。
- **Tabs**：同一对象的平级视图，保持 URL 或可恢复状态。
- **Modal**：只处理短任务和确认；复杂编辑使用独立页面。
- **Toast**：反馈短期结果，不承载必须阅读的错误细节。
- **Form**：label、帮助文本、字段错误、提交中和失败恢复齐全。
- **Table**：列宽与溢出可控，移动端提供降级方案。
- **Pagination**：与 filter/search 状态协同，切换后可恢复。
- **Empty State**：说明为何为空并提供合理下一步。
- **Error State**：说明可恢复动作，避免暴露内部错误。
- **Loading State**：使用局部骨架或进度，防止重复提交和布局跳动。

## 前端分层

- `app` / routes：路由、metadata 和页面组合。
- `components`：无业务或跨 feature 的展示组件。
- `features`：领域 UI、状态和用例编排。
- `lib/api`：HTTP client、错误映射和传输配置。
- `lib/auth`：客户端会话与授权辅助；服务端仍是权限事实来源。
- `types`：UI 专用类型或共享 DTO 的再导出。

## 管理后台

- 列表型任务优先表格，并提供状态标签、筛选器和分页。
- 处置动作显示目标、原因、影响范围和操作结果。
- 敏感及危险操作必须二次确认，防止重复提交。
- 每个处置对象应能进入关联操作日志或审计日志。
- 默认页面和普通管理员视图不得查询或展示真实身份。
